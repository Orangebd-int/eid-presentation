WSO2 Hosted Login Architecture Flow (Pattern 2)

RP App → WSO2 Hosted Form → eID API Verification → WSO2 MFA → RP App

🌐 Pattern 2: WSO2 Hosted Login UI

In Pattern 2, WSO2 Identity Server hosts the citizen login form directly. Citizens input their eID Number / Email and Password on WSO2's branded login interface.

🔌 eID REST API Verification

WSO2 validates citizen inputs by calling the eID Platform REST API (`/api/v1/auth/verify-credentials`) to verify credentials & check eID lifecycle state (`active`, `revoked`).

🔑 WSO2 Managed 2FA / MFA

Upon successful eID API verification, WSO2 Identity Server directly executes the 2-Factor Authentication step (TOTP Authenticator, SMS OTP, or WebAuthn FIDO2 passkey).

⚡ High Performance Caching

The eID API answers WSO2 in < 50ms using local Redis/PostgreSQL. Key2Data → Civil Registry is called only when demographic updates or initial enrolment is required.

⚖️ Pattern 2A Evaluation: Advantages & Trade-offs (WSO2 Hosted Form + eID REST API Verification)

In Pattern 2A, WSO2 hosts the citizen login page and delegates credential validation to the eID Platform via real-time REST API (/api/v1/auth/verify-credentials).

👍 Key Advantages (Pros)
  • ✓ Instant Revocation & Suspension Enforcement: eID Core validates credentials in real-time. If an eID is revoked or suspended, access is blocked immediately with zero sync delay.
  • ✓ Single Credential Vault (Single Source of Truth): Password hashes & WebAuthn keys remain strictly inside the eID Vault, avoiding credential duplication across external databases.
  • ✓ Sub-50ms Response Time: eID Core answers WSO2 in < 50ms using local Redis/PostgreSQL caching without calling Key2Data/Civil Registry during routine login.
  • ✓ Full Annex E Audit Log Integrity: Every verification attempt is logged in real-time within the eID Core Audit Trail (`authentication_audit_logs`).
⚖️ Architecture Trade-offs (Cons & Constraints)
  • ⚠️ Synchronous Outbound API Dependency: Citizen login requires an active HTTP REST connection between WSO2 IS and eID Core (`/api/v1/auth/verify-credentials`).
  • ⚠️ WSO2 Hosted UI Customisation Effort: WSO2 IS login templates must be customized using Sint Maarten government brand guidelines.
  • ⚠️ Custom Authenticator Requirement: WSO2 requires configuring a custom REST Authenticator extension to communicate with the eID Core API endpoint.
🚀 Relying Party (RP) Onboarding for SSO (Pattern 2 Workflow)
US-6.1 • US-6.2 • US-6.3 Compliant
🔑 Key Architecture Rule for RP Onboarding: Every Relying Party (COCI, Tax, Health) connects directly to WSO2 IS 7.0 (The Identity Broker), NOT directly to the eID Platform. WSO2 manages OAuth2 client_id credentials, hosted login UI binding, OIDC token issuance, and Pairwise Pseudonyms (PPID), while verifying credentials via the eID REST API.
Step 1 • US-6.1

Self-Service RP Registration

RP Developer registers their application inside WSO2 Developer Console, obtaining client_id, client_secret, and configuring authorized redirect URIs.

Step 2 • API Access

eID API Scope Authorization

WSO2 binds the hosted login form to eID REST API endpoint (/verify-credentials) using secure API client token authorization.

Step 3 • US-6.2

Sandbox Test Identities

RP tests authentication against sandbox identities in 4 distinct lifecycle states: active, pre_provisioned, under_review, and revoked.

Step 4 • US-6.3

Conformance Verification

Automated conformance harness validates PKCE (S256), pairwise claims (PPID), and OIDC Back-Channel Logout before go-live approval.

01

Step 1: RP App Redirects Citizen to WSO2 Hosted Login

GET /oauth2/authorize?client_id=coci-rp&response_type=code

The citizen clicks "Sign In with eID" on the Relying Party application (e.g. COCI Portal). The RP App redirects the browser to WSO2 IS 7.0 with PKCE authorization parameters.

02

Step 2: Citizen Inputs Credentials on WSO2 Hosted Form

WSO2 IS 7.0 Hosted HTML Form

WSO2 IS 7.0 displays its hosted login UI. The citizen enters their eID Number (`EID-SXM-26-XXXXXX-C`) or registered Email Address and password.

03

Step 3: WSO2 Calls eID Platform REST API to Verify Credentials

POST https://eid-api.gov.sx/api/v1/auth/verify-credentials

WSO2 IS 7.0 executes an outbound HTTPS REST call to the Sint Maarten eID Platform backend. The eID API verifies the password hash, checks eID lifecycle state (`active`, `revoked`), and returns citizen identity attributes in < 50ms.

04

Step 4: Key2Data → Civil Registry Sync (On-Demand Only)

POST /api/v1/key2data/civil-registry/verify-bsn

The eID API uses local Redis/PostgreSQL cache for routine logins. It calls Key2Data → Civil Registry only during initial enrolment or when demographic updates are required.

05

Step 5: WSO2 Executes 2-Factor Authentication (MFA)

WSO2 MFA Engine (TOTP / SMS / FIDO2)

Upon successful eID API verification, WSO2 IS 7.0 Prompts the citizen for 2-Factor Authentication (TOTP Authenticator code or SMS OTP) to achieve eIDAS Level High assurance.

06

Step 6: WSO2 Issues OIDC Tokens & PPID Claims to RP App

HTTP 302 Redirect to RP App /callback?code=AUTH_CODE

WSO2 IS 7.0 issues the authorization code, exchanges it for signed JWT ID Tokens with Pairwise Pseudonymous Identifiers (PPID), and completes the citizen login into the RP App!
