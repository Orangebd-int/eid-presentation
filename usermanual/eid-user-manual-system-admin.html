1. Introduction

As a System Administrator, you manage the eID platform from the System Administration Portal. You do not process citizen enrolments at the counter — that is the job of PSC operators — but you control who can access the platform and how external services connect to it.

  • Create and onboard new PSC operators with one-time login credentials
  • Activate or deactivate staff accounts across all internal roles
  • Browse enrolled citizen accounts (read-only directory view)
  • Review, approve, or reject relying party (RP) OIDC integration applications
  • Provision sandbox OAuth clients when an RP application is approved
  • Monitor platform-wide audit logs and security events
  • Oversee enrolment queue volume (read-only link to PSC portal)
Your responsibility: Every user lifecycle change and RP approval is recorded in the audit trail. Share one-time passwords securely. Never approve an RP application without verifying redirect URIs and business justification.

2. Sign in & sign out

How to sign in

  1. Open the eID website and click Sign in.
  2. Enter your work email address or eID number (format ID-SXM-…).
  3. Enter your password and click continue.
  4. Complete the second verification step (SMS code or authenticator app).
  5. After successful login, you are redirected to the System Administration Portal dashboard at /admin.
Staff login rule: Sign in with your eID number or email address. Username-only login (for example, admin) is not accepted for staff accounts.

How to sign out

  1. Look at the top-right corner of any admin page.
  2. Click Sign Out.
  3. Always sign out when leaving your workstation unattended.

Switching to the PSC portal or public site

  • PSC Portal (footer of left menu) — opens the PSC operator portal without signing you out.
  • Exit to Public Portal — returns to the citizen homepage without signing you out.

4. Dashboard

Menu path: Dashboard · URL: /admin

The dashboard is your home page. It shows:

  • Welcome banner — quick links to manage users and set up MFA if needed
  • System users — total count of internal staff accounts
  • Pending enrolments — applications in the PSC review queue (platform-wide)
  • Audit events — total recorded platform activity
  • Account security — whether MFA is enabled on your admin account

Quick actions

From the dashboard card you can jump directly to:

  • System users — user directory
  • RP applications — integration request queue
  • Audit logs — compliance search
  • Enrolment queue — PSC oversight (read-only view of pending applications)
  • Admin profile and Security settings
  • PSC portal — switch to operator view

Recent audit activity

The dashboard shows the five most recent audit events. Click View all to open the full audit log page with search and filters.

If your account security shows Setup recommended, go to Security & MFA and enable an authenticator app as soon as possible.

Activate or deactivate a staff account

  1. Open System Users and select the correct group card.
  2. Find the user in the table.
  3. Use the Staff access toggle to set the account to Active or Inactive.
  4. Wait for the success message confirming the change.
  5. Click Refresh if the list does not update immediately.
A deactivated user cannot sign in. Use this when an operator leaves the organisation or their access must be suspended immediately.

6. PSC operator onboarding

Only System Administrators can create new PSC operator accounts. This is done from /admin/users with the PSC Admin filter selected.

Create a new PSC operator

  1. Open System Users and click the PSC Admin filter card.
  2. Click Create PSC Admin (banner or section header).
  3. Complete the form:
    • Work email — required; used for login
    • Mobile number — required; used for SMS MFA
    • National ID — required for registry linkage
    • BSN — exactly 6 digits
    • Date of birth — required to generate the staff eID number
    • Username — optional; defaults from email if left blank
    • Display name — optional; for audit notes only
  4. Click Create PSC Admin.
  5. A credentials banner appears with one-time login details.

Share credentials securely

The banner shows (copy each field with the Copy button):

  • Login email
  • Login eID — newly generated staff eID number
  • Temporary password — shown once only
  • Username
The temporary password cannot be retrieved again after you dismiss the banner. Share credentials through a secure channel (in person or encrypted message). Instruct the new operator to sign in with email or eID, not username alone.

Verify the new operator

  1. Confirm the new user appears in the PSC Admin group with status Active.
  2. Ask the operator to sign in and complete SMS MFA.
  3. Confirm they land on the PSC Operator Portal at /psc.
  4. Check audit logs for event SYSTEM_USER_CREATED.

7. RP applications (relying party onboarding)

Menu path: RP Applications · URL: /admin/rp-applications

Government and partner services submit OIDC integration requests through the public form at /register-rp. You review each request here before a sandbox OAuth client is provisioned.

Filter cards

CardShows
Pending reviewApplications with status Submitted — need your decision
ApprovedApproved or production-active applications with provisioned clients
RejectedDeclined applications
All applicationsComplete history

Click a card to filter the queue on the left. The selected card shows how many applications match.

Review an application

  1. Select the Pending review card (default when work is waiting).
  2. Click an application in the Application queue list on the left.
  3. Review the detail panel on the right:
    • Organization and technical contact details
    • Integration path (WSO2 broker or direct OIDC)
    • Requested OAuth scopes and identity claims
    • Redirect URIs — verify each URL is correct and HTTPS in production
    • Business justification

Approve and provision a sandbox client

  1. On a Submitted application, scroll to Approve & provision sandbox.
  2. Adjust Approved scopes if needed (default: openid profile email).
  3. Select Approved claims — sub is always required and locked.
  4. Add optional review notes.
  5. Click Approve & provision client.
  6. Copy the credentials banner immediately:
    • Application reference
    • Client ID
    • Client secret — shown once only
    • OIDC discovery URL
  7. Share credentials securely with the RP technical contact.

Reject an application

  1. Scroll to Reject application.
  2. Enter a clear rejection reason (required).
  3. Click Reject application.
Do not approve redirect URIs you do not recognise. Do not share client secrets over unsecured email. Rejected applications remain in the Rejected filter for audit purposes.

8. Audit logs

Menu path: Audit Logs · URL: /admin/audit

The audit log records sign-ins, enrolment actions, OIDC events, user management, and security changes across the entire platform. Administrators have full read access.

Summary filter cards

  • Total events — all audit records (click to reset filters)
  • Today — events from the current day
  • Successful — success and approved outcomes
  • Failed / blocked — failures, rejections, and lockouts

Search and filter

  1. Use the search box to find events by email, eID, action name, or details text.
  2. Apply filters: outcome, action type, date range, actor role.
  3. Click a row to expand full event details.
  4. Use pagination at the bottom for large result sets.
  5. Click Refresh logs to load the latest events.

Events you should monitor as administrator

ActionMeaning
SYSTEM_USER_CREATEDNew PSC operator onboarded
SYSTEM_USER_STATUS_CHANGEStaff account activated or deactivated
SYSTEM_LOGIN / VERIFY_SYSTEM_MFAStaff sign-in activity
OIDC_TOKEN_ISSUEDCitizen or RP federation login
PROCESS_ENROLMENTPSC enrolment decisions
Audit details never show passwords or OTP codes. If you investigate a security incident, note the timestamp and action type, then contact IT support with those references.

9. Enrolment oversight

System Administrators monitor enrolment volume but do not replace PSC operators for processing applications.

What you can do

  • See Pending enrolments count on the admin dashboard
  • Open the PSC enrolment queue via the dashboard quick action (/psc/enrolments)
  • Review related events in audit logs (PROCESS_ENROLMENT, ASSISTED_ENROLMENT)

What PSC operators do instead

  • Approve, reject, escalate, or request documents on citizen applications
  • In-person counter enrolment
  • Fraud review and UIN reconciliation
For step-by-step enrolment processing instructions, see the PSC Operator User Manual.

10. Profile & security

Profile page

Menu path: Profile · URL: /admin/profile

  • View your administrator account details
  • Change your password (current password + new password, minimum 8 characters)
  • Update email or mobile (OTP confirmation required)

Security & MFA

Menu path: Security & MFA · URL: /admin/settings

SMS verification

Always enabled for your registered mobile number — used at sign-in.

Authenticator app (TOTP) — recommended

  1. Click Set up authenticator app.
  2. Scan the QR code with Google Authenticator, Microsoft Authenticator, or similar.
  3. Enter the 6-digit code to confirm.
  4. Your dashboard will show account security as Protected.

Passkey (optional)

  1. Click Register passkey.
  2. Follow your browser prompt (fingerprint, face, or device PIN).
  3. Passkeys allow passwordless sign-in on supported devices.
Protect your administrator account with MFA. Compromise of an admin account affects the entire platform.

What System Administrators can do

  • Full access to /admin/* pages
  • Create PSC operators and manage staff account status
  • Approve or reject RP applications and provision sandbox clients
  • Read all audit logs
  • Open PSC portal pages for oversight

What System Administrators cannot do

  • Process citizen enrolment decisions (PSC operator function)
  • Retrieve a temporary password or client secret after the one-time banner is dismissed
  • Delete or edit audit log entries
  • Change citizen account lifecycle from the Citizens directory tab (read-only today)

12. Troubleshooting common messages

Message you seeWhat it meansWhat to do
Could not load RP applications API or network error Click Refresh queue. Verify the eID API is running.
Review notes are required to reject Rejection reason field is empty Enter a clear explanation before rejecting an RP application.
Could not create PSC admin Validation failed or duplicate email/NID Check all required fields. Verify the email is not already registered.
Could not update user status Status change failed Refresh the page and try again. You may not deactivate your own account.
No applications in this view Selected filter has zero matches Try another filter card (for example, All applications).
Loading admin portal… (stuck) Session expired or network issue Refresh the page. Sign in again if redirected to login.
Invalid code. Try again. Wrong MFA code Wait for a new TOTP code (30 seconds) and re-enter carefully.

When to contact IT support

  • RP approval succeeds but the RP cannot authenticate — check discovery URL and redirect URI match
  • Audit logs show repeated failed admin logins
  • Platform API unavailable for extended period
  • You suspect unauthorized changes to staff accounts
