WSO2 Identity Server & API Manager — Server Setup

Step-by-step instructions to upload, configure, and run WSO2 on Ubuntu Linux using Docker Compose. Covers MySQL setup, federation to the eID API, firewall, and post-deployment verification.

1. Overview

WSO2 acts as the government SSO broker. Relying Party applications authenticate against WSO2, which federates login to the Sint Maarten eID platform.

Government Apps (RP) → WSO2 IS :9443 → eID API :5026 → eID Frontend :3000
ComponentImagePorts
WSO2 Identity Serverwso2/wso2is:5.11.09443 (HTTPS), 9763 (HTTP)
WSO2 API Managerwso2/wso2am:3.2.08280, 8243, 8244
MySQLHost or Docker3306
Deploy order: MySQL → eID API → eID Frontend → WSO2 → WSO2 federation config. WSO2 must be able to reach the eID API on the host before federation will work.

3. Install prerequisites on Ubuntu

SSH into your Ubuntu server as a user with sudo access, then run:

3.1 Update system packages

sudo apt update && sudo apt upgrade -y

3.2 Install Docker Engine

# Install Docker (official convenience script)
curl -fsSL https://get.docker.com | sudo sh

# Add your user to the docker group (log out and back in after this)
sudo usermod -aG docker $USER

# Verify
docker --version
docker compose version

3.3 Install MySQL client (optional, for DB setup)

sudo apt install -y mysql-client git unzip
If MySQL runs on the same Ubuntu server (not in Docker), install it with: sudo apt install -y mysql-server and secure it with sudo mysql_secure_installation.

4. Upload project to server

The WSO2 project lives in the onegov-wso2 repository. Choose one upload method:

Option A — Git clone (recommended)

# On the Ubuntu server
sudo mkdir -p /opt/eid-platform
sudo chown $USER:$USER /opt/eid-platform
cd /opt/eid-platform

git clone <your-git-repo-url>/onegov-wso2.git
cd onegov-wso2

Option B — SCP from your local machine

# Run from your local machine (replace user@server)
scp -r /path/to/onegov-wso2 user@your-server-ip:/opt/eid-platform/

Option C — rsync (keeps files in sync)

rsync -avz --exclude '.git' \
  /path/to/onegov-wso2/ \
  user@your-server-ip:/opt/eid-platform/onegov-wso2/
After upload, confirm these files exist on the server: docker-compose.yml, .env, scripts/mysql-init.sql

5. MySQL database setup

WSO2 requires three MySQL databases. Run the init script against your MySQL server.

5.1 Create WSO2 databases and user

# If MySQL is on the same Ubuntu server:
sudo mysql -u root -p < /opt/eid-platform/onegov-wso2/scripts/mysql-init.sql

# Or connect to a remote MySQL host:
mysql -h YOUR_MYSQL_HOST -u root -p < /opt/eid-platform/onegov-wso2/scripts/mysql-init.sql

This creates:

  • wso2_carbon_db — Identity Server config & registry
  • wso2_apim_db — API Manager data
  • wso2_apim_stats_db — API statistics
  • User wso2_user with password wso2_password (change in production)

5.2 Docker network (if MySQL runs in Docker)

If you use a shared Docker MySQL container on network docker-services_laravel_network:

docker network create docker-services_laravel_network 2>/dev/null || true

If MySQL runs on the Ubuntu host (not Docker), set DB_HOST=host.docker.internal in .env and ensure extra_hosts is present in docker-compose.yml (already configured for wso2-is).

6. Configure environment

Edit the .env file in the project root:

cd /opt/eid-platform/onegov-wso2
cp .env .env.backup   # backup first
nano .env

6.1 Example .env — MySQL on Ubuntu host

WSO2_IS_PORT_HTTPS=9443
WSO2_IS_PORT_HTTP=9763
WSO2_APIM_PORT_HTTPS=9443
WSO2_APIM_PORT_HTTP=8280
WSO2_APIM_PORT_SERVLET=8243

# MySQL on same Ubuntu server (accessible from Docker via host.docker.internal)
DB_HOST=host.docker.internal
DB_PORT=3306
DB_USERNAME=wso2_user
DB_PASSWORD=CHANGE_ME_STRONG_PASSWORD

6.2 Example .env — MySQL in Docker container

DB_HOST=laravel_shared_mysql
DB_PORT=3306
DB_USERNAME=wso2_user
DB_PASSWORD=CHANGE_ME_STRONG_PASSWORD
Linux note: The docker-compose.yml already includes extra_hosts: host.docker.internal:host-gateway on the wso2-is service. This is required so WSO2 can reach the eID API running on the Ubuntu host at port 5026.

7. Start WSO2 containers

cd /opt/eid-platform/onegov-wso2

# Pull images and start in background
docker compose pull
docker compose up -d

# Watch startup logs (WSO2 takes 2–3 minutes)
docker compose logs -f wso2-is

Wait until you see WSO2 Carbon started in the logs. Press Ctrl+C to stop following logs.

7.1 Check container status

docker compose ps

Both wso2-identity-server and wso2-api-manager should show Up.

7.2 Enable auto-start on reboot

# Docker restart policy is already "on-failure" in docker-compose.yml
# Ensure Docker itself starts on boot:
sudo systemctl enable docker
sudo systemctl start docker

8. Firewall (UFW)

# Allow SSH first (do not lock yourself out)
sudo ufw allow OpenSSH

# WSO2 HTTPS admin & OAuth
sudo ufw allow 9443/tcp

# WSO2 API Gateway (if exposed directly)
sudo ufw allow 8280/tcp
sudo ufw allow 8243/tcp

# Enable firewall
sudo ufw enable
sudo ufw status
In production, place nginx in front of WSO2 and only expose port 443 publicly. Keep 9443 internal or VPN-only if possible.

9. Verify deployment

9.1 Admin console

Open in browser: https://YOUR_SERVER_IP:9443/carbon/

Default credentials: admin / admin — change immediately.

9.2 Command-line checks

# WSO2 admin login page
curl -sk https://localhost:9443/carbon/admin/login.jsp -o /dev/null -w "HTTP %{http_code}\n"

# OIDC discovery
curl -sk https://localhost:9443/oauth2/.well-known/openid-configuration | head -5

# Federation prerequisites (eID API must be running first)
chmod +x scripts/verify-eid-federation.sh
./scripts/verify-eid-federation.sh

10. eID federation setup

After eID API and eID Frontend are running, configure WSO2 to broker login to eID.

10.1 Register eID as external OIDC IdP

  1. Log in to https://<server>:9443/carbon/
  2. Go to Identity Providers → Add
  3. Name: SXM_eID, Authenticator: OpenID Connect
  4. Configure OIDC endpoints (Ubuntu / Docker on same host):
FieldValue
Client Ideid-wso2-broker-client
Client Secreteid-wso2-secret-2026! (change in production)
Authorization Endpointhttp://host.docker.internal:5026/connect/authorize
Token Endpointhttp://host.docker.internal:5026/connect/token
UserInfo Endpointhttp://host.docker.internal:5026/connect/userinfo
JWKS URIhttp://host.docker.internal:5026/connect/jwks
Issuerhttp://localhost:5026 (or your public API URL)

10.2 Additional federation steps

  • Enable PKCE (S256) on the federated OIDC authenticator
  • Create custom claims: uin, citizen_status
  • Map eID claims to WSO2 claim URIs
  • Set SXM_eID as the Default Identity Provider
Full step-by-step federation guide with claim mapping tables: see onegov-wso2/EID_FEDERATION_SETUP.md in the repository.

11. Production hardening

  • Change WSO2 admin password from admin/admin on first login
  • Use strong unique MySQL password for wso2_user
  • Replace self-signed cert with a proper TLS certificate (or terminate SSL at nginx)
  • Restrict port 9443 to internal network or VPN
  • Back up Docker volumes: wso2-is-repository, wso2-apim-repository
  • Monitor container health: docker compose ps and log rotation

13. Troubleshooting

ProblemSolution
Container exits immediatelyCheck logs: docker compose logs wso2-is. Usually MySQL connection failed — verify DB_HOST and credentials.
Network not foundCreate it: docker network create docker-services_laravel_network
WSO2 slow to startNormal — wait 2–3 minutes. Check health: docker compose ps
Cannot reach eID API from WSO2Ensure extra_hosts: host.docker.internal:host-gateway is set and eID API listens on 0.0.0.0:5026
Federation token errorUse host.docker.internal for token/userinfo/jwks endpoints, not localhost
Port 9443 connection refusedContainer still starting, or UFW blocking — run sudo ufw allow 9443/tcp
