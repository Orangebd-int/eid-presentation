Sint Maarten eID API (.NET) — Server Setup

1. Overview

The eID API is the core Identity Provider backend. It handles authentication, MFA, citizen enrolment, OIDC token issuance, and admin operations. It connects to MySQL and serves the eID Frontend and WSO2 broker.

ItemValue
FrameworkASP.NET Core (.NET 10)
Default port5026
Project pathSintMaarten.EID/SintMaarten.EID.Api/
DatabaseMySQL — eid_mvp_db
MigrationsApplied automatically on startup
Swagger (dev)/swagger
OIDC discovery/.well-known/openid-configuration
Deploy the eID API before WSO2 federation setup. WSO2 must reach this API on port 5026.

3. Install .NET 10 on Ubuntu

# Update packages
sudo apt update && sudo apt upgrade -y
sudo apt install -y wget curl git unzip

# Install .NET 10 SDK and ASP.NET Core runtime
wget https://dot.net/v1/dotnet-install.sh -O dotnet-install.sh
chmod +x dotnet-install.sh
./dotnet-install.sh --channel 10.0

# Add to PATH permanently
echo 'export DOTNET_ROOT=$HOME/.dotnet' >> ~/.bashrc
echo 'export PATH=$PATH:$HOME/.dotnet:$HOME/.dotnet/tools' >>> ~/.bashrc
source ~/.bashrc

# Verify
dotnet --version
dotnet --list-runtimes
For production you only need the ASP.NET Core runtime, but the SDK is required on the build server to run dotnet publish.

4. Upload project to server

Option A — Git clone

sudo mkdir -p /opt/eid-platform
sudo chown $USER:$USER /opt/eid-platform
cd /opt/eid-platform

git clone <your-git-repo-url>/eid-with-dotnet.git
cd eid-with-dotnet/SintMaarten.EID/SintMaarten.EID.Api

Option B — SCP / rsync from local machine

# SCP
scp -r /path/to/eid-with-dotnet user@your-server-ip:/opt/eid-platform/

# rsync (excludes bin/obj)
rsync -avz --exclude 'bin' --exclude 'obj' --exclude '.git' \
  /path/to/eid-with-dotnet/ \
  user@your-server-ip:/opt/eid-platform/eid-with-dotnet/

5. MySQL database setup

Create the eID database and user. The API runs EF Core migrations on first start — you only need an empty database.

5.1 Install MySQL (if not already installed)

sudo apt install -y mysql-server
sudo mysql_secure_installation

5.2 Create database and user

sudo mysql -u root -p

Then run these SQL commands:

CREATE DATABASE IF NOT EXISTS eid_mvp_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'eid_mvp_user'@'localhost' IDENTIFIED BY 'CHANGE_ME_STRONG_PASSWORD';
CREATE USER IF NOT EXISTS 'eid_mvp_user'@'127.0.0.1' IDENTIFIED BY 'CHANGE_ME_STRONG_PASSWORD';

GRANT ALL PRIVILEGES ON eid_mvp_db.* TO 'eid_mvp_user'@'localhost';
GRANT ALL PRIVILEGES ON eid_mvp_db.* TO 'eid_mvp_user'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;

5.3 Create document storage directory

sudo mkdir -p /var/eid/documents
sudo chown www-data:www-data /var/eid/documents
sudo chmod 750 /var/eid/documents

6. Environment configuration

ASP.NET Core reads settings from environment variables. Use double underscore (__) as the section separator. Store secrets in a file, not in appsettings.json.

6.1 Create environment file

sudo mkdir -p /etc/eid-api
sudo nano /etc/eid-api/env

6.2 Production environment variables

# /etc/eid-api/env
ASPNETCORE_ENVIRONMENT=Production
ASPNETCORE_URLS=http://127.0.0.1:5026

# Database
ConnectionStrings__DefaultConnection=Server=127.0.0.1;Port=3306;Database=eid_mvp_db;User=eid_mvp_user;Password=CHANGE_ME_STRONG_PASSWORD;

# JWT — generate a random 64+ character secret
Jwt__Issuer=https://eid-api.gov.sx
Jwt__Audience=SintMaartenEID.RelyingParties
Jwt__Secret=REPLACE_WITH_RANDOM_64_CHAR_SECRET

# OIDC — must match your public URLs
Oidc__Issuer=https://eid-api.gov.sx
Oidc__LoginUrl=https://eid.gov.sx/login
Oidc__AuthorizationEndpoint=https://eid-api.gov.sx/connect/authorize
Oidc__TokenEndpoint=https://eid-api.gov.sx/connect/token
Oidc__UserinfoEndpoint=https://eid-api.gov.sx/connect/userinfo
Oidc__JwksUri=https://eid-api.gov.sx/connect/jwks
Oidc__EndSessionEndpoint=https://eid-api.gov.sx/connect/logout

# Document storage
EnrolmentDocuments__StorageRoot=/var/eid/documents

# SMS — disable demo mode in production
SMS__DemoMode=false
SMS__ApiEndpoint=https://your-sms-provider.example/api
SMS__ApiKey=YOUR_SMS_API_KEY
SMS__SenderId=GOVSXM
SMS__CountryCode=1721

# Civil registry integration
Key2Data__Mode=live
Key2Data__BaseUrl=https://api.key2data.gov.sx
Key2Data__OfflineMode=false
# Secure the env file
sudo chmod 600 /etc/eid-api/env
sudo chown root:root /etc/eid-api/env
Replace eid-api.gov.sx and eid.gov.sx with your actual domain names. All OIDC URLs must be consistent — mismatched issuer or login URL breaks WSO2 federation.

7. Build & publish

cd /opt/eid-platform/eid-with-dotnet/SintMaarten.EID/SintMaarten.EID.Api

# Restore packages and publish Release build
dotnet restore
dotnet publish -c Release -o /opt/eid-api/publish

# Set ownership for the service user
sudo chown -R www-data:www-data /opt/eid-api/publish
sudo chown -R www-data:www-data /var/eid/documents

7.1 Test run (manual, before systemd)

# Load env and test
set -a && source /etc/eid-api/env && set +a
cd /opt/eid-api/publish
dotnet SintMaarten.EID.Api.dll

In another terminal:

curl -s http://127.0.0.1:5026/.well-known/openid-configuration | head -5

Press Ctrl+C to stop the test run once verified.

8. systemd service

Create a systemd unit so the API starts automatically on boot.

sudo nano /etc/systemd/system/eid-api.service
[Unit]
Description=Sint Maarten eID Platform API
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/eid-api/publish
ExecStart=/home/YOUR_USER/.dotnet/dotnet /opt/eid-api/publish/SintMaarten.EID.Api.dll
Restart=always
RestartSec=10
EnvironmentFile=/etc/eid-api/env

# Security hardening
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/eid/documents /opt/eid-api/publish

[Install]
WantedBy=multi-user.target
Replace /home/YOUR_USER/.dotnet/dotnet with the output of which dotnet. If .NET is installed system-wide, use /usr/bin/dotnet. 
sudo systemctl daemon-reload
sudo systemctl enable eid-api
sudo systemctl start eid-api
sudo systemctl status eid-api

# View live logs
sudo journalctl -u eid-api -f

9. nginx reverse proxy

Expose the API over HTTPS. The API itself listens on localhost:5026 only.

sudo apt install -y nginx
sudo nano /etc/nginx/sites-available/eid-api
server {
    listen 80;
    server_name eid-api.gov.sx;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name eid-api.gov.sx;

    ssl_certificate     /etc/ssl/certs/eid-api.gov.sx.crt;
    ssl_certificate_key /etc/ssl/private/eid-api.gov.sx.key;

    client_max_body_size 20M;

    location / {
        proxy_pass http://127.0.0.1:5026;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
sudo ln -s /etc/nginx/sites-available/eid-api /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
Use Let's Encrypt for free TLS certificates: sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx -d eid-api.gov.sx

10. Firewall

sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status

Port 5026 stays internal (localhost only). Public traffic goes through nginx on 443.

11. Verify deployment

# Service running
sudo systemctl is-active eid-api

# OIDC discovery (local)
curl -s http://127.0.0.1:5026/.well-known/openid-configuration | grep issuer

# OIDC discovery (public HTTPS)
curl -s https://eid-api.gov.sx/.well-known/openid-configuration | grep issuer

# JWKS endpoint
curl -s https://eid-api.gov.sx/connect/jwks | head -3

# Swagger (if enabled)
curl -s -o /dev/null -w "HTTP %{http_code}\n" https://eid-api.gov.sx/swagger/index.html

13. Troubleshooting

ProblemSolution
Port 5026 already in usesudo lsof -i :5026 — stop duplicate process or old instance
Migration failed on startupCheck DB credentials in /etc/eid-api/env. Verify user has GRANT on eid_mvp_db
502 Bad Gateway from nginxAPI not running — sudo systemctl status eid-api
dotnet command not found in systemdUse full path from which dotnet in ExecStart
CORS errors in browserAdd production frontend URL to CORS policy in Program.cs, rebuild and redeploy
WSO2 cannot reach APIEnsure API binds to 0.0.0.0:5026 or use nginx internal proxy; check UFW rules
Permission denied on documentssudo chown www-data:www-data /var/eid/documents
