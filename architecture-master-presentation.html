Sint Maarten eID Master Architecture Comparison

Side-by-Side Analysis, Advantages/Disadvantages & Final Recommendation

RECOMMENDED
🪪

Pattern 1: eID Federated IDP

eID Core Hosts Login UI & FIDO2 Passkey Ceremony

RP App → WSO2 Broker → eID Core IDP (Login & FIDO2) → Key2Data (On-Demand) → Tokens to RP
✓ Key Advantages
  • Native FIDO2 Passkeys: Full support for Apple Touch ID, Face ID & YubiKeys.
  • Zero Password Exposure: WSO2 never touches raw citizen passwords.
  • eIDAS High Compliant: Hardware token binding at IDP layer.
  • Sub-50ms Speed: eID local Redis caching for routine logins.
  • Privacy First: Isolated identity vault with PPID support.
✕ Trade-offs
  • Requires browser redirection to id.gov.sx domain.
  • Requires eID team to maintain citizen login UI templates.
🌐

Pattern 2: WSO2 Hosted Form

WSO2 Hosts Login UI & Calls eID REST API

RP App → WSO2 Hosted Form → eID REST API (/verify) → WSO2 MFA Step → Tokens to RP
✓ Key Advantages
  • Single UI template managed inside WSO2 admin dashboard.
  • Simpler setup for legacy back-office internal apps.
  • Centralized WSO2 step-up authentication rules.
✕ Trade-offs
  • No Native FIDO2 Passkeys: Cannot run WebAuthn ceremony natively inside WSO2 form.
  • Security Risk: Broker layer processes raw citizen passwords.
  • Higher API network latency (~180ms per login).
  • Harder to achieve eIDAS Level High certification.

Final Executive Technical Recommendation

Ministry of General Affairs • Sint Maarten eID Platform

1. Primary Production Standard — Pattern 1 (eID Federated IDP):
We strongly recommend Pattern 1 as the primary national standard for all public-facing citizen applications (COCI Portal, Tax & Revenue Portal, Public Health Registry). Pattern 1 provides native FIDO2 WebAuthn Passkey support (Apple Touch ID, Face ID, YubiKeys), guarantees strict eIDAS Level High security certification, and ensures zero citizen credential exposure to intermediate broker layers.

2. Optional Hybrid Co-existence:
The eID Core Architecture natively supports both patterns simultaneously. Pattern 2 can be retained as an optional fallback connector for legacy internal back-office staff applications that require simple form embedding.
